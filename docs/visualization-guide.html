STATS 401 · Group 7 · Visualization handoff

From a task to a defensible shortlist

The explorer uses the prepared data already in this checkout. Views 1, 2, 4, and 5 have been revised; the existing evolution map remains integrated and interactive. Explanations below each visualization describe its What–Why–How choices. This guide records setup, the demonstration path, evidence boundaries, and course connections.

Run the source

From Final_Project, with Node.js installed:

node scripts/serve_preview.js 8769

Open http://127.0.0.1:8769/final.html. Stop with Ctrl+C. The server binds only to the local computer. It opens the final explorer by default at /. The original interim remains at index.html.

Alternatively, use Python 3: python -m http.server 8769 --bind 127.0.0.1. If Windows Python aliases or local network access fail, use the Node command above. No data collection, API credentials, or package installation is required. D3 7.9.0 and optional fonts load from CDNs, so D3 needs internet access. Serve over HTTP rather than opening the HTML file directly.

Source: final.html (structure), final.css (appearance), final.js (D3 and shared state). The browser reads data/final/view_data.json rather than the full long benchmark and feedback tables. The input data files are unchanged by this visualization revision.

A complete demonstration

  1. In Tasks or the matrix's Selected task control, choose Document understanding. The full window has 346 task-tagged records and 100 rule-inferred experience reports, out of 21,674 eligible records. Switch the count definition to compare these measures; the denominator remains all eligible feedback. Read the definition, DocVQA mapping rationale, and paged source sample. Use the coverage control to inspect unmapped tasks without inventing quantitative evidence.
  2. In Shortlist, select Top 5, Top 10, or Custom k. Family, license, openness, and total-parameter filters determine eligibility. The selected sort determines what “top” means; ties use model name. These are evidence orders, not recommendations.
  3. Select a task–model cell with the pointer or Enter/Space. Read B/E/C, raw scores, sources, practical excerpts, and missing mappings. Family-only reports stay separate from exact-model records.
  4. Use Use as model A, inspect a second candidate, and use Use as model B. The persistent comparison tray names both choices. Assigning the model already in the other slot swaps the pair; native selectors can also show the same model, with an explicit notice.
  5. In Compare, inspect the profile and raw-score table. Restore eight-axis example selects Qwen2.5-VL-7B-Instruct and Qwen2-VL-7B-Instruct. Both have all eight published dimensions; their source table does not fully specify evaluation settings. Switch an axis's protocol to see how evidence availability changes.
  6. From either metadata card, choose Inspect development for dated relationships or Practical reports for the selected task's attributed community evidence. Both routes preserve the chosen model and task.
  7. In Ecosystem, switch repository creation and verified release modes, isolate a family, and brush a period. Check the exact-value table. The acquisition month, October 2026, is explicitly partial through October 17.

Six interaction types support this sequence: filtering, sorting, selection, brushing/linking, variable switching, and evidence drill-down. Native month inputs provide the keyboard alternative to brushing. Native task phrase/ranking buttons and SVG nodes/matrix cells accept Enter and Space; the radar's markers expose exact values through focus labels and its table.

01 · Ecosystem growth

A D3 stacked area chart shows cumulative counts within the selected window. Family is color; time is position. Monthly steps avoid implying a continuously observed release process. Repository creation includes retained originals, fine-tunes, adapters, quantizations, and unknown types; a separate mode counts only canonical models with verified release evidence. The exact table lists new monthly totals, cumulative totals, per-family increments, and period totals. Hatching and an explicit date identify the partial acquisition month.

Use the family selector or legend buttons to isolate small layers. The area chart supports overview and composition; small or similarly colored layers require filtering or the table for precise comparison. There is no all-model release census here.

02 · Task explorer

The prepared corpus supports eight task definitions and five benchmark-mapped tasks. Only 1,965 of 21,674 full-snapshot feedback records have at least one supported task label. The view therefore visualizes the prepared taxonomy rather than inventing free-text topics. D3 creates responsive native phrase buttons with count-scaled typography and ranked SVG bars for precise comparison. All tasks stay visible at zero counts unless the user applies a local mapping filter. The phrase and ranking controls are keyboard accessible and retain selection while their evidence updates.

Switch between all task-tagged records and rule-inferred experience reports, filter mapped/unmapped definitions, or order by count/name. The experience subset is based on recorded usage-observation/problem-report categories and equivalent prepared experience labels; it does not confirm actual use or independent users. Percentages always divide by all eligible feedback under the shared family/platform/month filters. Summing across tasks would double-count multi-label records, so the view never uses that sum as its denominator. Mapping badges describe the existence of a task-to-benchmark definition, rather than complete model coverage or proven suitability.

Selection reveals the task definition, exact counts, rationale, benchmark definition links, and inclusion phrases. “Inspect model candidates” leads to the same task in the matrix. The excerpt browser deduplicates retained IDs and pages four snippets at a time; experience mode shows only matching experience snippets. Its sample-size and truncation labels remain distinct from aggregate counts. If no excerpt was retained for a filtered window, the aggregate still stands. No sentiment distribution is inferred from unvalidated labels or the convenience sample.

The pure task-evidence.js helper calculates counts from all-scope task buckets only; model/family buckets repeat records and are excluded from task totals. Its Node regression checks cover scope duplication, multi-label overlap, shared filters, experience switching, mapping gaps, sample deduplication, and the full snapshot. This file is included in the public static bundle.

03 · Family evolution

The existing custom SVG timeline uses family lanes, model nodes, and curved sourced links. Position shows chronology, not distance in architecture or capability. Dashed release-sequence links establish order only; other recorded relationship types retain their meanings and sources. Missing release dates stay absent. Radar selections remain highlighted, and nodes reveal metadata, provenance, and comparison actions. Label expansion and relationship filtering support exploration; dense labels can still require isolating a family.

Course connections: Networks, Graphs, and Trees, Time and Text, Overview and detail.

04 · Two-model capability radar

Each axis uses a fixed published scale: seven dimensions have a 0–100 range; OCRBench v1 has 0–1,000 points. Radius is (score − minimum) / (maximum − minimum); a future lower-is-better dimension reverses direction. Missing, ambiguous, out-of-range, and unmatched-protocol results remain unavailable and break adjacent lines. Circles/solid lines and squares/dashed lines distinguish A and B in addition to color.

The default pair has 8/8 published dimensions for both models. This is a coverage statement. Shared source-table groups still leave evaluation details unspecified, and HallusionBench's reported average formula is unknown. The raw table preserves units, metric labels, versions, splits, protocol identifiers, and source links. Profile shape helps reading; polygon area is not a meaningful aggregate score. Restore and swap controls support comparison, while metadata buttons link to development and practical evidence.

Course connections: Multivariate Visualization, Marks and Channels, Coordinated views.

05 · Task–model evidence matrix

Models are rows and tasks are columns. B counts mapped benchmark dimensions with a qualified score; shade shows B divided by the number of mapped dimensions. E counts rule-inferred usage observations or problem reports, and C counts all eligible feedback attributed to the exact canonical model. E is a subset of C. None of these counts is a capability score. An unmapped task remains visibly unsupported by benchmarks.

Sorting uses selected-task benchmark coverage, experience count, model name, or known parameter size. Top-5/top-10/custom-k truncate this ordered eligible set; “All” removes the truncation. Larger sets use 14-row pages, and k never exceeds the canonical registry size. Unknown parameter sizes are excluded under a cap. A focused model outside the filters is explicitly identified in its evidence panel. Users designate A and B themselves after inspecting the scores and sources.

Course connections: Multivariate tables, Matrix representations, Linked views and details on demand.

Evidence and scope

The prepared snapshot contains 18,255 repositories, 57 canonical models, eight tasks, 21,674 cleaned feedback records, and 143,086 benchmark measurements. Counts refer to different units. Benchmarks use the full prepared snapshot; family filters apply to candidates, while time/platform filters affect community evidence. Radar models remain explicit even outside current filters. Repository activity and verified releases remain separate. This revision acquires no new data and makes no claim that repository attribution confirms use of an exact model variant.
