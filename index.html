BEFORE WE BEGIN, A LITTLE CONTEXT

What are MLLMs and What makes a model multimodal?

A multimodal large language model (MLLM) combines language with another input type. We focus on models that accept images and text: a scanned invoice, chart or photo can become the subject of a question. Open-weight means weights are available; licenses still govern use.

Why this matters. Researchers and developers face many models with different capability claims. Choosing one requires matching evidence to a task and size budget—not simply choosing the newest or most popular model.

We connect ecosystem trends, published benchmarks and community discussions to help you decide which models to test. Popularity and discussion frequency do not measure accuracy.

METHODS & QUALITY

Traceable data. Transparent comparisons.

Acquire & prepare

Preserve source IDs and dates; deduplicate, filter and retain unknown values. Publish source/cleaned data and reproducible Python scripts.

Analyze & visualize

Rule-code discussion tasks, aggregate distinct records and compare source-grouped benchmark scores. Build interactive views with D3.js and custom SVG.

Review & verify

Project-member feedback drives revisions. Regression tests and browser checks verify behavior; the review record separates these from independent user research.

Limits & next steps

Support-forum sampling, unvalidated rule labels and incomplete benchmark settings limit generalization. Next: human-label review, independent usability testing and task/hardware-matched evaluation.

Dimensions and comparison rules

Why these dimensions?

User discussion motivates the capability questions. Published benchmarks supply the measurements; mention counts do not become quality scores. Speed and memory require controlled tests on your hardware and stay outside the polygon.

How to compare

Pairs share at least four measured dimensions. Each axis uses a shared source group and fixed published range, shown on a 0–100 scale. Missing measurements stay gaps; polygon area is not overall quality. Some evaluation settings remain incomplete.

Choosing within a task and size

Read the rankings

Each model occupies its own row, preventing overlap. Compare scores within one benchmark/source group. The board shows up to three leading measured models in each size tier; ties and all other candidates remain accessible in the complete list.

Use the size groups

Groups are ≤4B, >4–10B, >10–40B and >40B total parameters. These are comparison bins, not measured hardware requirements. A tier leader is a strong candidate to test, not a universal best model.

Why fewer task choices?

The selector includes only tasks with usable scored models of known size in a shared source group. Unmeasured interests—including video—remain in the feedback collection; unsupported mappings are not presented as recommendations.

Evidence limits

Missing results are not zero. Benchmark coverage is uneven and settings may be incomplete. Check licensing, speed, memory and real examples before deployment.

Data acquisition & preparation

Raw API caches, selected source fields, official model cards, acquisition scripts and cleaned tables are in the repository. Benchmark records preserve the OpenVLM baseline and official model-card evidence. The 143,086 numeric benchmark rows are measurements—not additional models. Some first-fetch feedback responses were retained as selected fields; later raw-response samples do not reconstruct every original response.

Family/type and feedback labels are rule-generated and lack human accuracy validation. Source URLs, timestamps, exclusions and uncertainty are retained. Missing scores are never zero; model release dates never come from repository modification dates. Reproduction · Concern counts · Structural checks.

Acquisition & analysis

Hugging Face API discovery uses bounded popularity/recent queries and pagination. Model cards and OpenVLM supply metadata and benchmark evidence. GitHub issues and Hugging Face discussions supply independently identified source objects. Processing retains source/cleaned tables, URLs, timestamps, count ledgers and reproducible scripts. No Reddit corpus or synthetic feedback is claimed.

Task/aspect rules merge synonyms and retain mixed/non-evaluative feedback. Counts are source objects, not sentences or independent users. Exact-model and family attribution stay separate. Downloads, issue counts and sentiment are not performance scores.
